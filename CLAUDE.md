## Commands

```bash
npm run dev           # dev server on http://localhost:3000
npm run build         # production build
npm run lint          # ESLint
npm run typecheck     # next typegen + tsc (typegen creates the global LayoutProps/PageProps types)
npm run db:generate   # write a new SQL migration in ./drizzle after editing src/db/schema.ts
npm run db:migrate    # apply migrations (PGlite locally, or DATABASE_URL if set)
npm run db:seed       # load diagnosis codes; pass a CSV path to load the full list: npm run db:seed -- path.csv
```

First run: copy `.env.example` to `.env.local`, set `BETTER_AUTH_SECRET` (and `CRON_SECRET`; `SMTP_URL` is optional in dev), then run `npm run db:migrate && npm run db:seed`. To reset the local database, delete `.data/` and run those two commands again.

There is no test runner yet.

## What Tiba is

A responsive web app, installable on phones as a PWA (no native app), where clinicians write and sign visit notes tied to appointments and invoice them. Spec v2 turns it from a solo-clinician tool into a **practice** tool:

- **Two account types:** clinician (own appointments and notes, the shared practice patient list, invoices, their profile and contracts) and administrator (runs the practice: clinician accounts and contracts, every signed note, invoices and payments, insurance billing, patients and duplicate checks, locations, service agreements, performance, notifications, reviews; never writes notes). Patients have no account. They sign on the device and can leave reviews.
- **Clinical scope (20 Oct update):** therapy notes plus SOAP discipline notes (PT, OT, ST, RN/LPN, CNA/HHA) with CPT/G billing codes and the 8-minute rule; initial evaluations that set goals; progress notes that rate them and can prefill from the last signed note; and an aide service plan that must be signed before any aide visit note. Each clinician has a discipline that decides what they can write. Section 11 of the spec has the data model, permissions and acceptance criteria.
- **Practices and verification (built).** `practices` holds the name, `name_key`, country and logo. Every account (`clinicians`, the Better Auth user table, for both account types) has a `practiceId`, a `role` and a `status`. An admin's sign-up creates the practice; a clinician joins by signing up with the same name and stays `pending` until the admin activates them on `/admin/clinicians` (spec section 3, "Joining a practice").
- **Spec v2 is built** (every step in the spec's build order). Clinicians' own screens filter by `clinicianId`; admin screens read the whole practice through `clinicians.practice_id`.
- **Built so far:** sign-in (each account type lands in its own app), sign-up as in the v2 prototype (country, account type, logo required for admins, password 8+), the admin app shell with placeholder screens, clinicians joining a practice and the admin verifying them (Overview item, Clinicians screen, emails), forgot password, patient reviews (public form, review link, admin list, hide), admin Patients with Add patient, admin Appointments, admin Locations with Add location, the clinician Appointments screen (week strip, statuses, notes reminder, booking), Notes to do, the Tomorrow card and reminders, the Notes to do screen, the visit note editor (all note kinds and types of care, drafts, goals, prefill) with letterhead and time in/out, and an Invoices screen with PDF and email. Billing (spec step 4) is built: only signed visits are invoiceable, invoices have a due date, and the currency comes from the practice country. Admin invoice statuses (Unpaid, Paid, Issue) come with the admin Invoices screen.

## Architecture

**Stack:** Next.js 16 (App Router, Server Actions), TypeScript, Tailwind v4 + shadcn/ui (Base UI primitives), Drizzle ORM on PostgreSQL, Better Auth, Zod, signature_pad, @react-pdf/renderer.

**Database: one schema, two drivers** ([src/db/index.ts](src/db/index.ts)). If `DATABASE_URL` is set, the app uses postgres-js against a real server. Otherwise it uses **PGlite**, real Postgres running in-process and stored in `.data/pglite`. PGlite allows one open instance per folder, so it is cached on `globalThis`. A force-killed server can leave `.data/pglite/postmaster.pid` behind; `removeStaleLock` deletes it on start only when it's empty. A non-empty stale lock ("-42 /pglite/data …") can leave the folder unopenable ("Aborted()"), so stop servers with Ctrl+C rather than killing them, and copy `.data/` before risky experiments. Stop `next dev`/`next start` before running `db:migrate` or `db:seed`, because two processes on one folder can corrupt it. `@electric-sql/pglite` is in `serverExternalPackages` and must stay there. `drizzle-kit` is only used for `generate`; migrations are applied by [scripts/migrate.ts](scripts/migrate.ts), so `drizzle-kit migrate`/`studio` are not wired up.

**Schema** ([src/db/schema.ts](src/db/schema.ts)):
- Better Auth's `user` model is the `clinicians` table, mapped in [src/lib/auth.ts](src/lib/auth.ts). Auth table columns must keep the field names Better Auth expects; when adding a Better Auth plugin, add its tables and fields by hand.
- **Practices** ([src/lib/practice.ts](src/lib/practice.ts), [practice-join.ts](src/lib/practice-join.ts)): names match by `normalisePracticeName` ([practice-name.ts](src/lib/practice-name.ts)), which must agree with the SQL in `drizzle/0006`. `clinicians.practice_name` and `country` are copies of the practice's, kept so they ride in the session; `updatePractice` updates the practice and every member's copy together. Only the admin (or a clinician in a pre-v2 practice with no admin, see `canEditPractice`) may change the name or logo.
- **Practice logo** (`practices.logo`) is stored as a PNG/JPEG data URL (required for admins, so every practice with an admin has one). The browser resizes uploads to 512px in [logo-upload.tsx](src/components/logo-upload.tsx), and the server checks the format and the file's real type with `parseLogoDataUrl` in [practice-logo.ts](src/lib/practice-logo.ts). SVG is never stored. The logo deliberately isn't a Better Auth field, so it stays out of the session. Pages show it through the private route `/api/practice-logo?v=<updatedAt>` (`practiceLogoUrl()`); don't embed the data URL in pages. Save changes with `updatePractice` in [practice-actions.ts](src/lib/practice-actions.ts), which also bumps `updatedAt`, and that busts the image cache.
- **Patients belong to the practice** (`patients.practice_id`) and are assigned to one clinician (`clinician_id`, which is how clinicians still find them). They also carry the spec's insurer, services ordered, ordering doctor, referral date, start of care, `status` (active or discharged) and `added_by_id`. Admins add them on `/admin/patients/new` (`addPatient`, with the name and date-of-birth duplicate check) and discharge or reactivate them on `/admin/patients`. Clinicians' patient search and bookings only offer **active** patients. Options for insurers and services live in [src/lib/patient-options.ts](src/lib/patient-options.ts).
- **Duplicate review** (`/admin/patients/[id]/duplicate`, `confirmNewPatient` and `mergeIntoExisting` in `src/app/admin/patients/actions.ts`): the existing record and the new entry side by side, matching fields in green. **Confirm new patient** clears the flag. **Merge into existing** moves the entry's appointments (with their notes) and invoices to the kept record, adds its diagnosis codes, fills details the kept record is missing, and sets the entry to `status = 'merged'` with `merged_into_id`. Merged records are hidden from every list and the duplicate check; a clinician opening one is redirected to the kept record. Flags show in Overview ("Check possible duplicate: …") and as the count on the Patients menu item (`possibleDuplicates` in [practice.ts](src/lib/practice.ts)).
- **Admin billing and notes** (queries in [src/lib/admin-billing.ts](src/lib/admin-billing.ts), all scoped to the practice):
  - **Completed notes** (`/admin/notes`, `/admin/notes/[appointmentId]`): every signed note, newest first, clinician filter, Billed / Not billed. The admin's signed note shows the visit, "Not billed yet · N days since signing · amount to insurer", the note as signed (amendment line, signatures, addenda; read-only), Download PDF and **Mark as billed** (`markNotesBilled`). Billing lives in `note_billings`, not on the locked note.
  - **Insurance billing** (`/admin/billing`): Waiting to bill and Billed, oldest first; over 30 days (`OVERDUE_DAYS`) is red, with a banner, an Overview item and the menu badge. **Send reminder** emails the admin (decided 21 Oct 2026: reminders go to the admin) the notes waiting, oldest first, patients as "Amina W." (`sendBillingReminder` in [src/lib/billing-reminders.ts](src/lib/billing-reminders.ts); each send is logged in `billing_reminders` and shown as "Last sent …"). The hourly cron also calls `notifyUnbilledOverdue`, which gives the admin one unread "N notes unbilled for 30+ days" notification at a time; it's marked read once nothing is over 30 days.
  - **Invoices** (`/admin/invoices`, `/admin/invoices/[id]`, actions in `src/app/admin/invoices/actions.ts`): Unpaid, Paid and Issues tabs with counts, clinician filter, totals per currency, New (until opened: `markInvoiceSeen` runs from the browser, or Mark all as seen), days since sent, Overdue after 30 days. An invoice shows details, visits and its history (`invoice_events`: sent, issue_flagged, issue_resolved, paid), with **Record payment** (date, method from `paymentMethods(country)`), **Flag issue** (category and a required comment; notifies the clinician, who sees "Issue" and the comment on their Recent invoices) and **Resolve issue** (back to Unpaid). Admins show numbers as "INV-0007" (`invoiceLabel`).
  - **PDFs:** `/api/notes/[id]/pdf` and `/api/invoices/[id]/pdf` serve a clinician their own and the admin any in the practice (`pdfScope` in [src/lib/pdf-scope.ts](src/lib/pdf-scope.ts)).
  - **Patient details** (`/admin/patients/[id]`, linked from the list): details, Care (clinician, insurer, referral, start of care: `updatePatientCare`), Discharge or Reactivate, the duplicate notice. Service agreement and documents come with step 8.
- **Missed visits** (`appointments.missed_at`/`missed_reason`, both or neither): the clinician marks a visit missed from the visit page once it was due and while it has no note (`markVisitMissed`/`undoVisitMissed` in `appointments/[id]/missed-actions.ts`, reasons in [missed-reasons.ts](src/lib/missed-reasons.ts)). A missed visit shows the **Missed** badge, leaves Notes to do and the invoice list, and is counted in Performance. A trigger in [drizzle/0028](drizzle/0028_lock_missed_visits.sql) refuses marking a visit with a note or invoice as missed, and refuses notes or invoice items for a missed visit.
- **Performance** (`/admin/performance?period=7d|30d|90d|180d|year`, 30 days by default): [src/lib/performance.ts](src/lib/performance.ts) `practicePerformance` returns patients admitted (added, start of care or referral in the period; merged excluded), invoices created in the period by status with totals per currency, missed visits per clinician, and reviews (hidden ones excluded). "This year" starts on 1 January in the admin's `time_zone`.
- **Admin Overview** (`src/app/admin/page.tsx`, extra queries in [src/lib/overview.ts](src/lib/overview.ts)): **Needs your attention** rows (clinicians to verify, notes unbilled 30+ days with "N days ago", agreements the client signed that need the admin's signature, contract replies and signatures, new invoices, invoice issues, possible duplicates, deactivated accounts, new reviews with "In the last two weeks"), then **Today across the practice** (`TodayVisits`: the server sends visits 36 hours either side and the browser keeps its own today, with Finished and Missed badges).
- **Admin Appointments** (`/admin/appointments`) lists upcoming visits for every clinician in the practice; the browser groups them by local day.
- **Locations** (`locations` table, `/admin/locations` and `/admin/locations/new`, `addLocation`): name, facility, address (optional only for Telehealth) and at least one service (a check constraint). Options live in [src/lib/location-options.ts](src/lib/location-options.ts). **Clinicians are based at one location** (`clinicians.location_id`, null until the admin sets it; not a Better Auth field): the admin adds or removes them on the location profile (`setClinicianLocation` in `src/app/admin/locations/actions.ts`; adding someone based elsewhere moves them). The location shows on the Clinicians list ("Mental health therapist · Camden"), the clinician's page and the Locations list (clinician count).
- **`DiagnosisPicker`** ([diagnosis-picker.tsx](src/components/diagnosis-picker.tsx)) is the spec's type-to-filter combobox; pass it a search Server Action.
- Clinical tables (patients, appointments, notes, invoices) carry `clinicianId`. **Always filter by the signed-in clinician** in the clinician app. Admin queries filter by `practiceId` (through `clinicians.practice_id`) and must never reach another practice.
- **Countries and money** ([src/lib/countries.ts](src/lib/countries.ts)): `practices.country` (copied to `clinicians.country`) is any ISO 3166-1 code (a check allows `^[A-Z]{2}$`; the app checks `isCountryCode`). `currencyFor(country)` gives its standard ISO 4217 currency (all 249 countries; Panama and Zimbabwe use USD). Sign-up offers every country, starting at the browser's region. **Billing currency:** admins can pick any currency in Settings (`practices.currency`, null = the country's); read it with `practiceBilling(practiceId)` ([practice.ts](src/lib/practice.ts)), never from `clinicians.country` alone. Admins change both with `updatePractice({ country, currency })`. **Every visit stores the currency it was booked in** (`appointments.currency`), and an invoice takes its visits' currency, so changing the billing currency never changes a booked fee or a sent invoice; an invoice can't mix currencies, and the booking form only pre-fills fees from the current currency. Money is stored as integer **minor units of that currency**: `currencyDigits` (0 for JPY, UGX…, 3 for KWD, BHD…, else 2) is a fixed table, not read from Intl, so stored amounts mean the same everywhere. Format with `formatMoney(minor, country, currency?)` (the `en-<country>` locale: "$80.00", "Ksh 8,000.00", "£80.00", "¥8,000"), parse fee inputs with `parseMoneyToMinor` (PDFs too: their font prints every symbol). Country and currency **names** differ slightly between the server's and the browser's Intl data, so pickers render them after mount (`useMounted`) to avoid hydration errors. Insurers: `insurersFor(country)` (US and Kenya lists, general kinds elsewhere).
- Age is calculated from `dateOfBirth`, never stored.

**Rules enforced by the database, not just the UI:**
- **Signed notes are locked.** A trigger in [drizzle/0001_lock_signed_notes.sql](drizzle/0001_lock_signed_notes.sql) rejects any UPDATE or DELETE once `signed_at` is set. There are two ways to correct one: **amend** it (`drizzle/0015`: the trigger only lets a signed note reopen when the signed version is already copied, unchanged, into `note_versions`, the note becomes `version + 1` with an `amendment_reason`, and both signatures are cleared), or add an **addendum** (`note_addenda`, locked by `drizzle/0014`). `note_versions` rows can never be changed or deleted. A check constraint stops a note being marked signed without `clinician_signature`. The patient's signature is optional, so collect it *before* the clinician signs.
- **Patient reviews can't be deleted or edited.** A trigger in [drizzle/0010_protect_reviews.sql](drizzle/0010_protect_reviews.sql) blocks DELETE (unless the whole practice is being removed) and any change except `seen_at`, `hidden_at` and `hidden_by_id`. Admins hide and show reviews with `setReviewHidden`; hidden reviews don't count towards the average or new-review counts.
- **Gap-free invoice numbers:** in the same transaction that inserts the invoice, run `UPDATE clinicians SET last_invoice_number = last_invoice_number + 1 ... RETURNING` (as `createInvoice` does). Don't use a Postgres sequence, because sequences skip numbers on rollback. `invoice_items.appointment_id` is unique, so a visit can only be invoiced once.

**Invoices screen** (`src/app/(app)/invoices/`):
- **Only signed visits** can be ticked (unsigned ones show "Sign the note to invoice"); `createInvoice` re-checks it. The create dialog asks **Payment due** (`DUE_OPTIONS`/`DUE_ORDER` in `periods.ts`: on receipt, 14 or 30 days), stored as `invoices.due_date` counted from the invoice date in the clinician's time zone. Each invoice stores its visits' `currency` (visits in another currency are greyed out with "Booked in USD" once one is ticked), so changing the country or billing currency never changes old invoices; the PDF and email show the due date and amounts in that currency.
- The visit list covers the look-back period (`periods.ts`) up to now, across all patients. One invoice can combine any signed visits, **for one patient or several** (decided 22 Oct 2026; "Tick all N ready to invoice" ticks a whole period). Visits for one patient bill that patient as before. Visits for several leave `invoices.patient_id` null: the clinician bills the **practice**, the PDF adds a Patient column, a patient's saved email is never pre-filled or saved, and the dialog warns not to send it to a patient. Lists show "3 patients" through `invoicePatientLabel` ([invoice-patients.ts](src/lib/invoice-patients.ts); queries must `leftJoin` patients). One currency per invoice still. The server re-checks that every visit belongs to the clinician, is signed, has already happened and isn't on another invoice.
- When an email address is given, `createInvoice` emails the PDF after the transaction commits. A failed send doesn't undo the invoice; it comes back as `emailError`, and the user can resend from Recent invoices. The address is saved to `patients.invoice_email` to pre-fill the next invoice. `invoices.sent_to` and `sent_at` record the send.
- The PDF comes from [src/lib/invoice-pdf.tsx](src/lib/invoice-pdf.tsx) (`@react-pdf/renderer`, DejaVu Sans via `PDF_FONT`, built from `pdf-kit`) with the same letterhead content as `NoteLetterhead`. It's served privately at `/api/invoices/[id]/pdf`. Times print in `clinicians.time_zone`.
- A `"use server"` file may only export async functions, so shared constants such as `PERIODS` live in separate modules.

**Email** ([src/lib/email.ts](src/lib/email.ts)): nodemailer over `SMTP_URL` (any provider), sending from `EMAIL_FROM`. Without `SMTP_URL` in development, emails are written to `.data/outbox/*.eml`; open them in a mail app to check them. Production throws `EmailNotConfiguredError`, which the actions turn into friendly copy. Build bodies with `renderEmail()` (pass `action` for a button link). Never log email contents or recipients.
- Hand-written SQL (extensions, triggers) goes in `npm run db:generate -- --custom --name <name>` migrations. `0000_init.sql` was edited to start with `CREATE EXTENSION pg_trgm`.

**Search** uses the `pg_trgm` GIN indexes on `patients.full_name` and `diagnosis_codes`. For typo-tolerant name search, use `word_similarity(q, full_name) > 0.3 OR full_name ILIKE '%'||q||'%'`, ordered by `word_similarity`. The default `%` operator compares against the whole name and misses typos like "amna" for "Amina Wanjiru".

**Diagnosis codes:** [data/diagnosis-codes.sample.csv](data/diagnosis-codes.sample.csv) is a small sample (ICD-10, F/Z codes). The full list depends on the market: WHO ICD-10 needs a licence, while ICD-10-CM (US) is public domain.

**Auth** ([src/lib/auth.ts](src/lib/auth.ts)):
- Email and password with at least 8 characters (spec v2), plus optional TOTP 2FA.
- **Sign in** tells an unknown email apart from a wrong password: after `INVALID_EMAIL_OR_PASSWORD` it calls `explainSignInFailure` (`(auth)/sign-in/actions.ts`, rate-limited per IP), as the spec asks. "Keep me signed in" is Better Auth's `rememberMe` (sessions still end after 30 idle minutes).
- **Forgot password:** `/forgot-password` calls `requestPasswordResetLink` ([actions.ts](src/app/(auth)/forgot-password/actions.ts)), which refuses unregistered emails (a deliberate spec choice; Better Auth's own endpoint answers the same either way), allows one link per account per minute (checked against `verifications` rows `reset-password:*`), then calls `auth.api.requestPasswordReset`. `sendResetPassword` in `auth.ts` emails the link (1 hour, `RESET_LINK_SECONDS`). The link goes through `/api/auth/reset-password/:token`, which redirects to `/reset-password?token=…` (or `?error=INVALID_TOKEN`); that page calls `authClient.resetPassword`. `revokeSessionsOnPasswordReset` signs the account out everywhere. Both pages are public, so they're excluded in the `proxy.ts` matcher.
- **Account fields:** `practiceName`, `role` and `country` come from the sign-up form; `practiceId` and `status` are `input: false` and set only by `placeNewAccount` (the `databaseHooks.user.create.before` hook), which creates or joins the practice and throws `APIError` codes (`PRACTICE_TAKEN`, `PRACTICE_NOT_FOUND`, `PRACTICE_HAS_NO_ADMIN`) that the sign-up page turns into copy. The `create.after` hook emails the admin about a waiting clinician.
- **Protected fields:** the `update.before` hook refuses any Better Auth update touching `role`, `status`, `practiceId`, `practiceName` or `country` (a hook's returned data is merged into the original, so a field can't just be dropped). Tiba changes them with Drizzle directly: `setClinicianStatus` in `src/app/admin/clinicians/actions.ts` (admin only, same practice, deletes the clinician's sessions on deactivation) and `updatePractice`. A trigger in [drizzle/0005_lock_account_role.sql](drizzle/0005_lock_account_role.sql) also blocks role changes in the database.
- **Routing:** `/` sends each account home with `homeFor(user)`: admins to `/admin`, active clinicians to `/appointments`, pending or deactivated clinicians to `/pending` (the waiting page in `(auth)`). Sign-in, two-factor and sign-up all go to `/`. Clinician pages use `requireClinician()`, which only lets **active** clinicians through; admin pages (`src/app/admin/`) use `requireAdmin()`. `requireAccount()` accepts any signed-in account (narrowing `practiceId` to a string) and is only for things everyone shares, like practice details.
- Sessions expire after **30 minutes of inactivity** (`expiresIn` + `updateAge`), because the device is handed to patients.
- [src/proxy.ts](src/proxy.ts) (Next 16's renamed middleware) only checks that a session cookie exists. **Every page and Server Action that reads patient data must call `requireClinician()` (or `requireAdmin()` in the admin app).**
- Better Auth rejects requests whose `Origin` isn't `BETTER_AUTH_URL` with an "Invalid origin" error. In development `trustedOrigins` also allows `127.0.0.1` and LAN addresses (`192.168.*`, `10.*`), and `next.config.ts` has matching `allowedDevOrigins`. This means a phone on the same Wi-Fi can use the Network URL that `next dev` prints. Production trusts only `BETTER_AUTH_URL`.

**Routes:**
- `src/app/(auth)/` holds sign-in, sign-up, the 2FA step, forgot and reset password, `/pending` (clinicians waiting for verification), `/review` (the public patient review form) and `/reviews` ("Check reviews from patients": admins go to `/admin/reviews`, clinicians see a notice).
- **Patient reviews:** `/review` is public (excluded in `proxy.ts`). Its Server Actions in `(auth)/review/actions.ts` validate everything, only reveal a practice's name and active clinicians' names, only accept practices with an admin, use a honeypot field, and are rate-limited per IP by [src/lib/rate-limit.ts](src/lib/rate-limit.ts) (in-memory, per process). `/review?practice=<id>` is the practice's shareable link. Reviews are marked read by `markReviewsSeen`, called from the browser after the admin's list shows (marking during render ran twice through redirects and hid the New badges).
- **Sign-in return path:** `proxy.ts` sends signed-out visitors to `/sign-in?next=<path>`, and sign-in goes back there after checking it with `safeNextPath` ([src/lib/safe-next.ts](src/lib/safe-next.ts)), which only allows paths inside Tiba.
- `src/app/admin/` is the admin app: its layout calls `requireAdmin()` and renders `AppShell app="admin"` (practice logo and name at the top, the prototype's grouped menu, phone tabs Overview, Patients, Billing and More). `ADMIN_SECTIONS` in `nav-items.ts` lists every admin screen with its header copy; `admin/[section]/page.tsx` shows a placeholder for any section not built yet, so a built screen just gets its own folder. Overview, Settings and More have their own pages.
- `src/app/(app)/` holds the clinician app's signed-in screens; its layout calls `requireClinician()` and renders `AppShell`. The clinician nav follows the v2 prototype: Appointments, Notes to do, Patients, Invoices (kept from v1.1), Contracts, Notifications, Profile and Settings. Every clinician screen in the nav is built. The visit note is opened from an appointment or a draft, so it has no nav entry. Build screens in the order in spec section 11, using the details in spec section 14.
- Better Auth's handler is at `src/app/api/auth/[...all]`.

**Settings, discipline and notifications:**
- **Clinician Settings** (`/settings`, Account tab on phones): Your role (discipline, saved on change), Notes and signing (the patient's signature is always offered and optional, so there's no "patients sign" toggle), Invoicing (country and billing currency read-only, plus the **visit fee** in that currency, which pre-fills bookings when there's no earlier fee for the type of care), practice details and a privacy line. Discipline and visit fee aren't in the session; read them with `clinicianSettings` ([src/lib/account.ts](src/lib/account.ts)).
- **Discipline** ([src/lib/disciplines.ts](src/lib/disciplines.ts)): RN, LPN, PT, OT, SLP, HHA/CNA or MH (`clinicians.discipline`, null until set, which allows every note). `canWriteCare` maps each to its types of care (MH: the therapy types) and `kindsForDiscipline` limits LPNs to visit notes. The visit page shows "This note is for another discipline" instead of the editor, and `saveNoteDraft`, `signNote` and `startAmendment` refuse with `disciplineProblem`. Signed notes stay readable.
- **Notifications** ([src/lib/notifications.ts](src/lib/notifications.ts), `notifications` table, one row per recipient with a title, detail and the `href` it opens): `notifyAdmins` on a new invoice (`createInvoice`), a possible duplicate (clinician Add patient) and a new review; `clearNotifications` marks them read once handled (duplicate confirmed or merged, reviews opened). Both apps have a Notifications screen (`NotificationsList`: New badges, Mark all as read, opening one marks it read) and a count on the menu item (and the Account / More tab). Creating a notification never fails the work that caused it. Contract and invoice-issue notifications come with those screens.

**People and paperwork (spec v2 step 8):**
- **Files** ([src/lib/files.ts](src/lib/files.ts), `files` table, bytes in a `bytea` column until hosting is decided): uploads go to `POST /api/files` (multipart; a route, not a Server Action, so the 5 MB limit doesn't raise every action's body limit; same-origin only), downloads and removal to `/api/files/[id]`. The real type is read from the first bytes (PDF, Word, PNG, JPEG; locations PDF only, with a required description). Who can use a file follows its `owner_kind` (`canUseOwner`): `clinician` (their own Profile documents: they upload; the admin only downloads), `clinician_admin` (admin-only documents about a clinician), `patient`, `location`. UI: `FileList` and `FileSlot` in [file-list.tsx](src/components/file-list.tsx).
- **Clinician Profile** (`/profile`, `saveProfile`; [profiles.ts](src/lib/profiles.ts), [profile-data.ts](src/lib/profile-data.ts), `clinician_profiles`): discipline (also in Settings), speciality, licence (hidden for aides), education, certifications (Current / Expires soon within 60 days / Expired; aides and CNAs need one), contact details (phone, contact email that starts as the sign-in email, home address), career experience (role, employer, from/to months or "I work here now", summary) and the emergency contact (the admin can still correct it). Documents: one file each in the `PROFILE_DOCS` slots ([profiles.ts](src/lib/profiles.ts): ID document, resume, signed job description, W-9; the upload route only accepts these slot names), plus other documents with a required short description (checked by the route too). The clinician uploads, replaces, removes and downloads them; the admin downloads. Signed contracts are listed automatically. The admin's clinician page (`/admin/clinicians/[id]`) shows it all read-only, plus the emergency contact (`saveEmergencyContact`), admin-only documents, account status and Send contract.
- **Contracts** ([contracts.ts](src/lib/contracts.ts) wording and options, [contract-data.ts](src/lib/contract-data.ts) queries; admin actions in `src/app/admin/contracts/actions.ts`, clinician actions in `src/app/(app)/contracts/actions.ts`): Draft → Sent → Feedback (clinician messaged) → Sent again (Update and resend, re-signed) → Signed. The letterhead (address, phone, email, or an uploaded image replacing the text) is saved on the practice and copied onto the contract when sent. `ContractDocument` renders it for the live preview and both apps; `ContractThread` is the message thread. A trigger in [drizzle/0024_lock_paperwork.sql](drizzle/0024_lock_paperwork.sql) locks signed contracts and makes messages permanent, so a signed contract's "seen" can't be recorded: the admin learns of signatures through notifications (`contract_signed`, `contract_message`; clinicians get `contract`). Badges: `/contracts` (waiting to sign) and admin Contracts (unread contract notifications); both show on Overview.
- **Service agreements** (`/admin/patients/[id]/agreement`; [agreement-template.ts](src/lib/agreement-template.ts) for the details type, default wording, `{tokens}` and `[blanks]`; [agreements.ts](src/lib/agreements.ts); actions in `src/app/admin/patients/agreement-actions.ts`): modelled on a US home care agency's form, summarised in [docs/service-agreement-template.md](docs/service-agreement-template.md). The admin fills in the client, emergency contact, insurance, services table, rates, holidays and deposit (card numbers are never stored), pre-filled from the patient record; the client answers the authorizations, accepts or denies, and initials; then the client (or a responsible party) and the agency witness sign, or the witness records a refusal. Details can be saved first (`saveAgreementDetails`). The wording is the practice's (`practices.agreement_template`, edited at `/admin/settings/agreement`; null = `DEFAULT_CLAUSES`), and signing is refused while it has `[blanks]`. The first signature fixes the wording and details (`service_agreements.sections`, `details`); a complete agreement (both signatures, or a witnessed refusal) is locked by [drizzle/0026](drizzle/0026_lock_agreement_details.sql). Status badges: `AGREEMENT_BADGE`.
- **Location profile** (`/admin/locations/[id]`): details, the clinicians based there (`LocationClinicians`: add or remove), PDF files with descriptions, and Remove location (`removeLocation`; a dialog confirms and, when clinicians are based there, asks which location they move to; removes its files; refused for the last location).
- **PDFs:** built from the shared blocks in [pdf-kit.tsx](src/lib/pdf-kit.tsx), after the daily-note layout of therapy record systems: `RunningHeader` and `Footer` ("Page X of Y") on every page, `Section` (bold heading over a full-width rule; `keepTogether` for short ones), `Answer` (bold sub-heading), `DetailGrid` (bold "Label: value" in two columns), `Table` (even ruled lines), `Signatures` and `Clause` (legal text: short clauses stay on one page). Fixed elements must be pinned from the top (react-pdf drops ones positioned from the bottom). **Fonts** ([pdf-fonts.ts](src/lib/pdf-fonts.ts)): notes, patient records and invoices use DejaVu Sans (`PDF_FONT`, pinned `dejavu-fonts-ttf`); contracts and service agreements use Tinos (`SERIF_STACK`, pinned `@expo-google-fonts/tinos`), a free font with Times New Roman's letter widths, falling back to DejaVu for symbols it lacks. `next.config.ts` traces both fonts' files (`PDF_FONT_FILES`) into the routes that make PDFs; add new PDF routes there. The **note PDF** has the details grid, Diagnoses and Billing codes tables (minutes per code, total and units), the sections by group (Subjective, Objective…), the written note, signatures with the licence number, and addenda. PDFs: invoices, signed notes, contracts (`/api/contracts/[id]/pdf`, signed only), service agreements (`/api/agreements/[patientId]/pdf`, admin, fully signed) and the patient record (`/api/patients/[id]/pdf`, the clinician's own visits; `DownloadPdfButton` passes the time zone). File names never carry patient names.

**Patients screens** (`src/app/(app)/patients/`, queries in [src/lib/patients.ts](src/lib/patients.ts)):
- **Patients** lists every patient in the practice (spec v2: the list is shared) with age, your last visit, **Note to do** (one of your finished visits has no signed note), **Admin checking** and **Discharged**. Search runs in the browser over that list (word starts, plus one typo for words of 4+ letters), so names never go into a URL. A search with no match hands the typed name to Add patient through `sessionStorage`.
- **Add patient** (`addPatientAsClinician`): name, date of birth, phone, email, diagnosis, services ordered and ordering doctor; assigned to you. `checkDuplicate` runs as soon as both the name and date of birth are in ([patient-duplicates.ts](src/lib/patient-duplicates.ts), shared with the admin's `addPatient`). On a match the button becomes **Add and ask admin to check**, which saves `patients.duplicate_of_id` and `duplicate_flagged_at` for the admin to review.
- **Patient record** (`/patients/[id]`, any patient in your practice): "34 · Your patient since Feb 2026", **Finish note** / **Write note** (your latest draft or visit waiting for a note), **Create invoice** (disabled until you have a signed visit that isn't invoiced), Details, Diagnosis codes, **Care team** (services ordered, goals from the latest signed evaluation per discipline, aide service plan status) and **Your visits** with status. Aide visits show **Needs plan** until a plan is signed. Only your own visits show. The patient record PDF isn't built yet.
- Subqueries in `practicePatients` and `patientRecord` use written-out table names: Drizzle leaves columns unqualified inside `sql` subqueries, which made `id` ambiguous.

**Appointments screen** (`src/app/(app)/appointments/`):
- Server Actions live in `actions.ts`: list (a week at a time), `getNotesToDo` (finished visits without a note, and unsigned drafts), patient search, care types with their last fee, and create. Every one starts with `requireClinician()` and filters by `clinicianId`.
- The screen ([appointments-view.tsx](src/app/(app)/appointments/appointments-view.tsx)) follows the prototype: header "Today · Wednesday 21 October" / "3 appointments" (or "A free day") with **Back to today** and **Book a visit**; a Monday–Sunday week strip with arrows and a dot on days with notes to do; a lilac reminder linking to `/notes`; the day's visits with a status badge; then the Tomorrow card. Status comes from `statusOf`: Upcoming (outline), Needs note (warning), Draft (neutral), Signed and Invoiced (success), Missed (danger). Loading shows placeholder rows; a failed load shows Try again. The month calendar (FullCalendar) was removed.
- **Notes to do** (`src/app/(app)/notes/`): "Needs a note" (finished visits with no note, **Write note**) and "Drafts" (notes started but not signed, with when they were last edited), from [src/lib/notes.ts](src/lib/notes.ts). The same `notesToDoCounts` feeds the Appointments reminder and the count on the "Notes to do" menu item and phone tab (the clinician layout passes it as `badges`). Layouts don't re-render on client navigation, so actions that change notes should `revalidatePath("/", "layout")` to refresh that count. It has `loading.tsx` and `error.tsx` (Next 16 passes `retry`, which re-fetches). Drafts show "3 of 6" (sections done, counted like the editor's progress bar, with goal progress only when the patient has a signed evaluation) or **Ready to sign**, and "Amendment ·" when a signed note is being amended.
- **Visit length** is booked as hours plus minutes, from 10 minutes up to **24 hours** (aide shifts; checked in `bookingSchema`). Overnight visits show "08:00–07:30 next day", and a typed time out at or before the time in counts as the next morning (`visit-times.tsx`); the "now" buttons show on both days. `formatDuration` ([format.ts](src/lib/format.ts)) writes "50 min", "1 h 30 min", "24 h".
- `RelativeDay` and `EditedAt` ([relative-day.tsx](src/components/relative-day.tsx)) write "Today · 14:00", "Yesterday", "13 Oct" and "Edited 10:02" in the viewer's time zone.
- `src/lib/format.ts` formats times and dates in `en-GB` ("09:30", "Friday 17 October") whatever the browser's language.
- Times: the browser turns its local date and time into an ISO instant before calling the server, and the server stores `timestamptz`. Display always uses the viewer's local time.
- `/appointments/[id]` is the Visit note screen (see **Visit note** below). A signed note shows the locked view with the letterhead (`NoteLetterhead`).
  - **Time in and time out** (`appointments.time_in`/`time_out`) are recorded with `setVisitTimes` in `visit-times.tsx`. The one-tap "now" buttons appear only on the visit day; a typed time always counts as being on the visit's day. A check constraint requires time out to be after time in, and a trigger in `drizzle/0003` locks both times (and `starts_at`) once the note is signed. Before signing, the times show as editable inputs; after signing, they print in the details grid, on the note PDF and on invoices.
- **Tomorrow card and reminders** (`tomorrow-card.tsx`, `reminder-actions.ts`, [src/lib/reminders.ts](src/lib/reminders.ts)): "Email me tomorrow's list" sends immediately. The evening reminder is `clinicians.reminder_emails` plus `time_zone`, which is saved from the browser. `GET /api/cron/reminders` with `Authorization: Bearer $CRON_SECRET` sends at most one email per clinician per local day, after 6 pm in their time zone, so call it **hourly** from a scheduler (Vercel Cron, a GitHub Action, cron-job.org). Reminder emails show patients as "Amina W." only. Time-zone maths uses `temporal-polyfill`. The PDF must reuse the same letterhead layout. Show dates and times on server-rendered pages with `LocalDateTime`, because the server doesn't know the viewer's time zone.

**Visit note** (`src/app/(app)/appointments/[id]/`):
- **Templates** live in [src/lib/note-templates.ts](src/lib/note-templates.ts). A note has a `kind` (`progress`, `evaluation`, `service_plan`, `oasis`) and a `care` (therapy types `individual`, `couples`, `assessment`, `followup`, or disciplines `pt`, `ot`, `st`, `rn`, `hha`). `getTemplate(kind, care)` returns the groups and fields; `kindsFor(care, servicesOrdered)` decides which kinds the clinician can pick (OASIS needs RN, PT, OT or ST; the service plan is RN with HHA ordered). Answers are stored in `notes.fields` (jsonb) keyed by field id, so adding a section needs no migration. Field types are rendered by `NoteField` in [note-fields.tsx](src/components/note-fields.tsx); `ChoiceChip` is shared.
- **Billing** follows the 8-minute rule in `billableUnits`. Billing answers are never prefilled (`NOT_PREFILLED`).
- **Goals** come from the latest signed evaluation for the same patient and care, written by anyone in the practice. **Prefill** (`getPrefill`) copies the signed note of the same kind and care from the patient's most recent visit, written by anyone in the practice, and refuses notes from another practice. The offer and the "Copied from" line show that visit's date, not the signing date.
- **Aide visits** show `AideLock` until the patient has a signed service plan.
- **Autosave** (`note-editor.tsx`): every change bumps a `version`; a 900 ms debounce calls `saveNoteDraft`, saves never overlap (`inFlight`), and a save only clears the edits it sent (`savedVersion`). It also saves when the tab is hidden and warns on unload with unsaved changes. Update fields with the functional `changeFields`, never from a stale closure. When driving the page over DevTools, leave it untouched for about 3 s after typing: `Runtime.evaluate` calls stall pending page timers in headless Edge.
- **Sign note** (`/appointments/[id]/sign`, `sign/actions.ts`): a summary of the answers (`summarise` in [note-summary.ts](src/lib/note-summary.ts)), the clinician's pad (required) and the patient's pad (**always shown, never required**, so a note can be signed by the clinician alone). "Show {name} only this box" opens a full-screen pad that hides the note. `signNote` checks both PNGs (`isSignatureImage` in [signature.ts](src/lib/signature.ts)), re-checks the sections and the aide plan, refuses if the draft changed since the page opened (`draftSavedAt` must equal `notes.updated_at`), writes `notes.body` with `writeNote` (a fixed sentence pattern per type of care, times in the browser's time zone) and sets `signed_at` in one UPDATE. Goal lookups shared by the pages and the action live in [note-context.ts](src/lib/note-context.ts).
- **Signed note** (`signed-note.tsx`): lock banner, the written note on the letterhead, signature tiles (the patient's says "Didn't sign" when empty) and collapsed Section answers. Signatures are stored as PNG data URLs and drawn with `SignaturePad` ([signature-pad.tsx](src/components/signature-pad.tsx), `signature_pad` 5).
- **Note PDF** ([src/lib/note-pdf.tsx](src/lib/note-pdf.tsx), served privately at `/api/notes/[appointmentId]/pdf`, signed notes only): the same letterhead as the invoice PDF, the details, the written note, both signatures ("Signed electronically …") and the addenda. **Download PDF** passes the viewer's time zone as `?tz=` (not patient data); otherwise times use `clinicians.time_zone`, then UTC. The filename carries only the date.
- **Amendments** (`amend.tsx`, `startAmendment` and `cancelAmendment` in `amend-actions.ts`): **Amend note** on a signed note asks what needs correcting, copies the signed version into `note_versions` (the copy also keeps the visit times) and reopens the note in the editor as the next version, with `AmendmentBanner` above it (no prefill). Signing again finishes it; the patient may sign again but doesn't have to. **Cancel amendment** restores the last signed version exactly. The signed view shows "Amended · version N", the reason and **Earlier versions**; the PDF shows the amendment and when each earlier version was signed.
- **Addenda** (`addenda.tsx`, `addAddendum` in `addendum-actions.ts`): corrections listed under a signed note with when and who. Only the note's own clinician can add one. A trigger in [drizzle/0014_lock_note_addenda.sql](drizzle/0014_lock_note_addenda.sql) blocks editing or deleting an addendum and adding one to an unsigned note.

## Design system

- **Tokens** live in [src/app/globals.css](src/app/globals.css). Primitives in `src/components/ui/` are shadcn (Base UI), resized for the brand:
  - **Controls are 48px** (`h-12`), small ones 40px (`size="sm"`, `h-10`). The design system's minimum tap target is 44px.
  - **Buttons** are pills (`rounded-full`) with a 1.5px border and semibold text. Variants: `default` (fern), `secondary` (fern-100), `outline` (white, fern-300 border, fern text), `ghost` (fern text), `destructive`. Disabled is ink-100 with ink-400 text, not faded.
  - **Inputs, selects and text areas** are `rounded-md` (12px) with a 1.5px `border-input` (ink-300). On focus the border turns fern (`border-primary`) and the lilac ring shows. Placeholders are `text-subtle-foreground`.
  - **Badges** are 26px pills, 13px semibold, with `success`, `info`/`accent`, `warning`, `danger`, `neutral` and `outline` variants.
  - **Cards** are `rounded-lg` (16px) with `border-border-subtle` and `shadow-sm`. Dialogs and sheets are `rounded-xl` (24px) with `shadow-lg`. The checkbox is 20px with a 6px radius.
  - The spec's **Design system additions** (section 11): choice chips (`ChoiceChip`), the combobox (`DiagnosisPicker`), and the measures grid, level rows, goal editor and billing codes table (in `note-fields.tsx`) exist. The signature pad (`SignaturePad`) exists too. Notice banners, skeletons and the rest don't yet; build them as shared components in `src/components/` when the screens that need them are built.
  - The toast (`toast()` from `sonner`) is mounted once in the root layout, top-centre, light only.
- **Tiba components** live in `src/components/`:
  - [app-shell.tsx](src/components/app-shell.tsx): shared by both apps (`app="clinician"` or `"admin"` picks the navigation, because icon components can't be passed from a server layout). A side menu on `md` and up (footer: practice identity plus a sign-out icon); on phones, a top bar (logo plus the clinician's initials, which open Account) and a bottom tab bar. It respects the iPhone safe-area insets.
  - [nav-items.ts](src/components/nav-items.ts): `NAV_ITEMS` (desktop menu) and `TAB_ITEMS` (phone tabs Visits, Notes, Patients, Account). The Account tab is `/settings`; its `also` list keeps the tab lit on Profile, Contracts, Notifications and Invoices, which phones reach from the Account screen.
  - `PageHeader`: optional `back` link and `overline`, the title, a help line and actions. Start every screen with it, copying the overline and title from spec section 14.
  - `PracticeMark` (logo or initials in a frame, plus `initialsOf`) and `SignOutButton` (`iconOnly` for the side menu).
  - `EmptyState`: friendly "nothing here yet" panels.
  - `FormField`: a label, an input and an optional `hint`. Pass `input` to use another control.
  - `PasswordInput`: has a show/hide toggle and an optional leading `icon`.
  - `FormField` also takes `icon` (leading icon) and `error` (a field error under the field that replaces the hint and sets `aria-invalid`).
  - `Switch` (`src/components/ui/switch.tsx`, Base UI): the design-system toggle, 48 × 28px. Wrap it in a `<label>` with its text.
  - `FormAlert`: the form-level error box.
  - `LogoUpload`: picks and resizes the practice logo. It's used on sign-up and in `PracticeDetailsDialog`, which opens from Settings.
  - `Logo`.
- **Sign-in screens:** [src/app/(auth)/layout.tsx](src/app/(auth)/layout.tsx) shows the brand panel beside the form on `lg` screens and only the logo plus form on smaller ones. Start each auth page with `AuthHeading`.
- **Stale styles in dev:** a utility class used for the first time in a file created while `npm run dev` is running may be missing from the served CSS (an element stays hidden or unstyled). Restart the dev server before debugging it.
- **Shell sizes:** the phone top bar is 64px (`h-16`) and the tab bar is 72px with `shadow-up` instead of a border. Bars that sit above the tab bar use `bottom-[calc(72px+env(safe-area-inset-bottom))]`. Page gutters are 20px on phones (`px-5`) and 40px on desktop (`md:px-10`). Auth and settings forms use `max-w-form` (480px).
- **Phone layout:** `main` has bottom padding (`pb-28`) so content clears the bottom tab bar. Keep it if you change the shell. Use `grid-cols-1` (which is `minmax(0, 1fr)`) on page-level grids. A plain `grid` column grows to its widest content, and on phones that silently widens the whole page (`innerWidth` grows past the device width; it was 566px instead of 390px), so check `window.innerWidth` at 390px, not just horizontal scroll.
- **shadcn gotchas:**
  - `shadcn add` writes `import { cn } from "cn"` and installs the `cn` package (plus `next-themes` for sonner). We use `cn` from `@/lib/utils` (clsx + tailwind-merge) and have no theme switching, and ESLint errors on the `cn` import. After adding a component, fix its imports and `npm uninstall cn next-themes`.
  - Components that depend on `button` stop at a prompt asking to overwrite it. Back up `src/components/ui/button.tsx`, run `shadcn add <name> -y --overwrite`, then restore the button.

**Dependencies** are pinned to exact versions that were at least two weeks old when added. Keep new ones pinned the same way.

## Private health information

Everything sits behind the login. Never put patient data in logs, URLs, query strings, or analytics. Dev mode would log every Server Action's arguments; `logging.serverFunctions: false` in `next.config.ts` turns that off, so keep it. `.data/` holds the local database and is git-ignored. Hosting is not decided yet: it depends on the market (Kenya Data Protection Act and/or HIPAA with a BAA).

## Brand rules that affect code and copy

- **Palette:** [src/app/globals.css](src/app/globals.css) mirrors the design-system tokens: the scales (`--fern-50…900`, `--lilac-50…700`, `--ink-50…900`, `--red-*`, `--amber-*`) plus semantic names. Components use the semantic utilities only:
  - **Actions:** `bg-primary` (with `hover:bg-primary-hover`, `active:bg-primary-press`), `bg-secondary`, `bg-destructive`.
  - **Surfaces:** `bg-muted` (panel), `bg-accent` (lilac), `bg-sunken`.
  - **Text:** `text-muted-foreground`, `text-subtle-foreground`, `text-accent-foreground`.
  - **Borders:** `border-border` (default), `border-border-subtle` (cards, bars), `border-border-strong`, `border-border-action` (outline buttons).
  - **Disabled:** `bg-disabled`/`text-disabled-foreground`. Secondary buttons press to `bg-secondary-press`.
  - **Status pairs:** `bg-success`/`text-success-foreground`, and the same for `info`, `warning`, `danger` and `neutral`. Badge has matching variants.
  - **Focus:** the ring is 3px lilac-300 (`ring-ring`, at full strength).
  - **Radii** follow the design system: `rounded-xs` 6px, `rounded-sm` 10px (rows inside panels), `rounded-md` 12px (controls, alerts, small panels), `rounded-lg` 16px (cards), `rounded-xl` 24px (dialogs, sheets), `rounded-full` (buttons, badges, chips). Don't use `rounded-2xl` or larger.
  - **Shadows:** `shadow-xs`, `shadow-sm` (cards), `shadow-md` (hover, menus), `shadow-lg` (dialogs), `shadow-up` (bottom bars). Motion uses `ease-out` with 120ms (controls) or 200ms (cards, toggles).
  - Never write hex values in components; the email and PDF templates are the only exception, because they can't read CSS variables. There is no dark theme.
- **Type:** Young Serif (`font-heading`, applied to h1–h3 automatically, weight 400) and Figtree (`font-sans`). The design-system scale is available as `text-display`, `text-h1`, `text-h2`, `text-h3`, `text-title`, `text-body-lg`, `text-body`, `text-small`, `text-caption` and `text-overline` (each sets its own line height).
- **Layout:** the desktop layout starts at **860px**, because the `md` breakpoint is overridden in `globals.css`. Content is capped at **1120px** (`max-w-content`). Dates read "12 Sep 2026". Currency follows the practice country (see **Countries and money**).
- **Copy:** plain, warm, and brief. Say "you". Error messages say what to do next. Never use these words: *platform, solution, seamless, optimise, invalid*. Better Auth's own error messages break these rules (for example "Invalid email or password"), so map error codes to Tiba copy, as [sign-up](src/app/(auth)/sign-up/page.tsx) does. Don't joke about health or privacy.
